# 方块作品集：呈现参考

查阅日期：2026-10-09。选择作者本人项目页与产品官方页，借鉴内容结构，不复制界面或背书。以下为页面实际内容及本项目的编辑建议；作者的业务数字不作为独立核实的行业结论。

## 1. Knowledge Hub · Andrew Marks

[个人 AI 知识系统案例](https://www.andrewmarks.design/case-studies/knowledge-os)

**观察：**首屏用一句话说明产品用途，紧跟真实界面、角色、时间、系统和上线状态；后文交替呈现截图、架构与录屏。数字标注日期和来源，并明确个人使用证据与用户研究的区别。

**用于方块：**封面直接展示编辑式资料馆；用三个数字说明已交付资产。保留“36 条公开资料”和“293 页私人原件”各自口径，不相加成一个线上规模。来源阅读与失败保留证据各给一张大图，证明产品判断。

## 2. Ask Archive · Joseph Chen

[有边界的作品集 AI 助手](https://www.josephchenux.com/case-study/ask-assistant)

**观察：**用角色、范围和系统结构说明作者贡献；把按页面理解上下文、知识组织、回答边界分别展开。结果部分承认早期数据和低使用深度，讨论助手何时需要出现。

**用于方块：**截图旁批用“收起—选区—展开—保存”四格讲清楚。旁批图注明交互原型；已实现的来源阅读单独展示。把低介入设计作为成果，用图说明空间占用和注意力变化。

## 3. Microsoft Copilot / User Evaluation · Tashfeen Ahmed

[作者作品集中的两个 AI 项目](https://tashfeen.me/)

**观察：**项目介绍简短，快速交代应用场景与本人贡献，并链接正式产品资料；Copilot 成品经验和 Agent Mode 前期探索有不同表述。作品集本身采用画布、演示与可操作卡片。

**用于方块：**借鉴“一张结果图＋一个判断＋一句贡献”。六张成果页分别突出资料馆、阅读器、研究夹、规范政策、桌面方块、截图旁批。静态交付保留编号和节奏，后续放入网页时可补图像放大与短录屏。

## 4. 官方展示：Notion Enterprise Search

[官方产品页](https://www.notion.com/product/enterprise-search)

**观察：**首屏直接提供演示入口；按跨应用搜索、即时回答、可信来源等任务逐段放界面，而非堆技术名词；客户评价显示姓名、岗位及公司。

**用于方块：**成果标题用“找到案例”“回到原文”“留进研究夹”；每张图只标两三个关键点。试用反馈可写为“设计院同事内测反馈归纳”，用反馈、改动、对应画面的三列对应。未经确认的姓名、逐字引语和效率数字不填入成稿。

## 本次内容编排

最终交付 12 页：“1 页封面 → 7 页成果展示 → 1 页试用反馈 → 1 页 PRD 摘要 → 1 页工程验证 → 1 页贡献与下一步”。主线优先展示真实界面与交互状态，过程压缩成图注。首屏交代产品、职责、阶段与使用对象；PRD 用一页任务、优先级和验收摘要，5 页完整版作为附件。此编排与 PRD 位置是对上述参考的综合建议，不是来源页面原样模板。
