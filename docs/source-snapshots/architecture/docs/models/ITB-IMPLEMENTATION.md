| 可见图层 | 23，保留原始图层名称 |
| 展开后的三角面 | 2,625,469 → 2,607,683，主要依靠压缩与实例复用减轻负担，未大幅减面 |

| 浏览器实际绘制 | 总览 265 次绘制、2,644,471 三角面提交；包含透明材质额外绘制，不等同于文件面数 |
| 材质和纹理 | 工作副本按外观合并为 100 个基础材质、16 张纹理；网页继续去重和清理 |

工作副本导出当前可见模型空间内的 Mesh、Brep／Extrusion 自带渲染网格，保留块变换和共享几何。可见曲线 10 条未转换成表面；布局视口和隐藏内容不在网页模型内。没有缺失可见曲面的网格缓存。将 Rhino 的 Z 向上转换为网页的 Y 向上，并居中，原始坐标偏移保存在审计文件。

纹理从 3DM 嵌入内容读取，最长边限制为 1024，基础色、透明度及常规贴图已转换。不是完整的 Enscape 材质还原：渲染器专属效果、复杂材质、灯光不保证一致。场景颜色仅作模型展示；原设计效果仍以用户的图纸和渲染为准。

屋顶花园与 Layer0 的较大网格采用保边界的保守减面，目标比例 45%，误差阈值为单个网格半径的 0.05%。在误差和拓扑约束下，只减少约 1.8 万个展开三角面。没有为了达到 30–60 万面目标扩大误差或删除构件。后续若实机性能不足，应识别高成本植被／家具再做专用轻量版本，不能仅凭图层名称批量删减。

## 页面行为

- ITB 项目正文顶部增加 3D 模型区域，点击后才下载 Three.js 与 GLB。模型、贴图、解码器均随站点提供，不依赖第三方 CDN。
- 鼠标拖动旋转、滚轮缩放、右键平移；方向键平移及加减键缩放。
- 总览／俯视／正面／侧面四个通用视角，重置恢复视角及全部图层。
- 23 个图层独立开关，保持 Rhino 名称。没有虚构“保留结构”“改造前／后”的语义映射。
- 加载提示、下载进度、90 秒超时、失败重试、WebGL 中断提示。
- 可关闭模型释放资源；离开页面取消请求并释放几何、材质、纹理、观察器和 WebGL 上下文。
- 按需渲染，离开可视区域暂停绘制；像素比最高 1.5。窄屏显示 360px 高度及换行按钮。

## 验证与适用范围

环境：Windows 本机、Codex 内置 Chromium 浏览器、Astro production preview、localhost；用户说明 VPN 开启。没有网络限速，窄屏测试仍使用桌面 GPU。

| 检查 | 结果 |
|---|---|
| Astro 构建 | 11 个静态页面成功；Three.js 按需块超过 500KB 的体积提示仍存在，不作为首屏同步资源 |
| Khronos glTF 校验 | 工作副本、网页模型、解码并展开实例后的模型均为 0 errors / 0 warnings |
| 校验信息 | 非 2 次幂纹理尺寸；解码后有 2 个退化三角形。扩展本身不被校验器直接支持，因此额外做了解码后检查 |
| 完整性 | 工作副本三角面与当前可见源缓存展开统计一致；优化前后外包围盒最大边界差约 0.11mm；浏览器可见主体、拱顶及连廊。不是人工逐构件验收 |
| 首次打开 | 模型下载阶段 94ms；开始挂载到第一帧提交 633ms；不含动态脚本下载，不等于 GPU 完成或线上加载耗时 |
| 关闭后再打开 | 关闭后 canvas 数量 0，重新打开为 1；该次模型下载 34ms，第一帧提交 294ms，有缓存影响 |
| 离开到 About 再返回 | 返回后尚未打开时 canvas 为 0；再次加载成功，下载 55ms，第一帧提交 353ms |
| 交互 | 俯视、总览、图层关闭与重置可用；旋转后截图呈现不同朝向。滚轮操作时模型区域页面位置保持不动 |
| 图层效果 | 关闭屋顶花园后，绘制提交从 2,644,471 降至 1,404,840 三角面 |
| 窄屏 | 390×844 视口设置下页面可用宽度 375px，正文宽度 375px，没有横向溢出；模型显示、按钮换行及重置可用 |
| 失败降级 | 本地代理对模型返回 HTTP 503，界面出现“重新加载模型”和可继续阅读的提示 |

这些是开发者检查，不是 3–5 名真实用户任务测试，也不是跨浏览器、真实 Android／iOS、国内直连或线上性能认证。尚需真实手机触摸、持续交互帧率、多个浏览器、弱网和线上部署测试。当前没有证据表明已达到移动端 30–60 万面目标。

## 迭代记录

1. 导出可见渲染缓存，建立原始几何数量和材质基线；发现空 children 字段及 12 个零长度顶点法线，修正工作副本格式与法线后重新校验。未移动顶点。
2. 按图层组织实例批次及可合并网格，进行保守减面和 Meshopt 压缩；保留图层控制。模型降到 6.2 MiB。
3. 接入按需查看器，实测释放、返回和窄屏布局；修复图层标题被正文通用样式弱化的问题，补充请求失败测试。
4. 在测试中途重新构建后，返回页面触发旧／新脚本同时初始化，发现双画布。补充 DOM 级初始化标记，避免不同脚本模块重复绑定同一查看器；重新加载后连续两轮执行“到 About → 返回 → 打开模型 → 总览”，每轮 canvas 均为 1，侧面视角及总览截图正常。

## 复现入口

- `scripts/inspect-rhino.py`：读取源文件清单。
- `scripts/export-itb.py <source.3dm> .model-work/itb-working.glb`：需要 rhino3dm、numpy、Pillow；本机 rhino3dm 隔离安装在 `.model-tools/`。
- `node scripts/optimize-itb.mjs`：从工作副本生成网页 GLB 和统计。
- `node scripts/validate-itb.mjs`：检查工作副本、网页文件及解码后的几何。
- `npm run build`，然后 `npm run preview -- --host 127.0.0.1 --port 4322`。
- `node scripts/serve-model-test.mjs`：在 4324 提供仅用于本机的 503 失败场景，依赖 4322 预览。

后续需要用户确认的设计内容：原始命名视图对应的关键空间；哪些图层代表保留／新增；模型颜色是否希望进一步统一。AI 自然语言控制与 Case Study 页面属于后续工作。

## Astra 对项目的影响

官方 2026-09-04 建筑可视化案例展示了 Astra 通过 Blender Python API 建模、设置材质灯光、检查预览并迭代修正的工作方式：
https://developers.openai.com/blog/architectural-visualization-with-astra

对本项目的合理预期是更强的跨步骤代码与工具协作能力，有利于转换脚本、几何检查、查看器实现及调试。该案例不是 Rhino 无损转换或移动端性能的对比评测，不能据此声称有确定的 3D 精度提升百分比。网站运行仍由 GLB／Three.js 负责，换用 Astra 不要求重写网站，也不需要为基础查看器接入付费模型 API。
