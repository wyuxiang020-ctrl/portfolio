# 交互模型加载等待的定位与修复

本轮针对“模型已经减小但仍等待很久”检查完整加载链路。结论是：当前公网传输波动是主要瓶颈，代码另有可调整的串行等待。已将脚本与模型改为并行准备，并缩短范围请求的前置等待，保留原有建筑细节、下载校验、取消和重试。现有样本尚不能证明公网总时间稳定下降，不能写成“秒开”。

| 环节 | 原实现 | 本轮实现 | 证据边界 |

## 验证记录

- 22 项本地范围下载测试通过：真实 GLB、乱序拼接、缺失或变化的版本标记、完整请求回退、截断、损坏、503、停滞、总超时、取消、快速重开和重试。计时为刻意缩短的测试故障参数，不能当作生产体验。
- 4 项本地真实轻量 GLB 准备集成测试通过：单请求与范围请求哈希一致，503 保留原因，取消终止连接。模块延迟是确定性夹具，非真实 AI 响应。
- 生命周期最初 15 项通过；复核补充同时失败场景后发现上述归因问题，修复后 17 项通过。首次失败、首次通过和后续记录均保留。
- 构建通过，生成 11 个静态页面。仍有查看器脚本大于 500 KB 的构建提醒，其本身按需加载；本轮消除等待顺序，没有声称脚本已经变小。
- 本地生产构建在 Codex 内置浏览器中实际显示模型：首次点击至首次绘制提交 230 ms、控制可用 230 ms；下载 35 ms、GLB 解析 76 ms；关闭重开绘制提交 191 ms。样本为一次初开和一次重开，缓存状态非受控，不能与公网或历史本地样本作可靠提速比较。
- 浏览器实际完成俯视、隐藏场地、恢复全部、关闭、重开；故障测试服务器第一次返回 503，页面出现重试入口，再次点击恢复真实模型。见 `browser-first.json`、`browser-recovery.json` 和截图。
- 本地预览实际使用完整请求回退（`full-fallback`），恢复测试使用完整响应（`full`）；公网范围传输与哈希证据来自 Node，不能表述为公网浏览器范围加载已经验收。
- “首次绘制提交”是 JavaScript 完成提交，不是屏幕像素精确呈现时刻；控制可用也不等于真人确认可用。截图用于确认画面确实出现。

所有本轮浏览器操作由代理执行。真实手机触屏、不同运营商、无 VPN 国内直连、作者本人自测与真人任务测试仍未测。没有访客 LLM 调用、没有固定 AI 响应回放；本轮记录的是自动化软件和浏览器检查。未取得账户流量账单，费用不编造；新增付费服务为 0，访客模型 API 调用为 0。

## 演示和失败恢复

正常：打开项目末尾 → 点击打开模型 → 选择俯视或侧面 → 展开图层并隐藏场地 → 恢复全部 → 关闭模型继续阅读 → 再次打开。

失败：加载期间可以取消；超时、HTTP 失败或数据损坏时保留图纸阅读和重试入口。软件测试验证取消后的旧结果不会挂载到新尝试。已开始的浏览器动态脚本请求不能真正取消，可能继续完成并进入浏览器缓存；模型传输会终止，晚到的脚本不会打开已取消的模型。

## 仍未解决的限制和后续判断

公网约一分钟的模型传输仍是明显问题。本轮结束后不继续扩展模块；如下一轮要显著改善首次打开，应优先对比实际目标地区的静态资源分发链路，再决定是否迁移模型资源。另一可选项是单独的更小首屏预览模型，但需要保证院落与必要构件的表达，且必须重新量测，不能先承诺效果。重复减少材质已经不是本轮证据支持的首选方向。

真人任务脚本继续保留在[前轮任务记录](../2026-09-30/TASKS.md)中，状态未执行，不作为工程优化的前置条件。原建筑作品联合署名仍为 Yuxiang Wang 与 Han Liu；本轮是网站加载流程与验证工作，没有重新归属建筑设计成果。
