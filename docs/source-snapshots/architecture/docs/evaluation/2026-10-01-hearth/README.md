# 火塘完整模型传输修复 · 2026-10-01

演示标识：`spatial-ux-2026-10-01-hearth-r2`。本轮只处理火塘大模型传输，不改变模型、材质、图层、相机和建筑署名，不新增 AI 功能。前一轮完整报告保留于 `../2026-10-01/`，不覆盖失败记录。

## 发现与取舍

原公开模型 23,820,388 字节：JSON 1,687,344、纹理 9,888,570、Meshopt 几何 12,234,988，其余为对齐等。现有文件已采用实例化、WebP、Meshopt，精确去重只可节省约 64KB。Brotli 11 可压至 17,044,323 字节，但服务器完整响应已启用 Brotli；不能把重复压缩视为新的提速措施。没有依据删建筑构件或降纹理细节。

公开源支持 206 范围请求、强 ETag，命中缓存。小规模 4 × 256KiB 并发实验取回 1,048,576 字节，8.266 秒，逐段对应原文件；这是方案筛选样本，不能外推整个模型成功。别名连接也曾 12 秒超时，未据此换域名或承诺国内直连。

选定修复：仅火塘使用 512KiB 分段，先验首段后最多 4 个活动请求。每请求独立 45 秒停滞、整个尝试仍最多 300 秒。不是延长等待上限，也不是新增轻量模型。

## 完整性与失败恢复

- 每段校验 Content-Range、总长、实际收到长度与同一强 ETag；后续发送 If-Range。
- 分段响应必须无内容压缩或 identity，防止混淆压缩字节和原文件偏移。
- 成功拼接后核对 GLB 文件头、长度及构建时原文件 SHA256，再交给原查看器。哈希为 `21ab5b2a859f61ad308ec7df9f40c971fa47f3ca23aec36e4536415d0425b74a`。
- 首请求返回 200 时只读取一次完整响应；后续不支持范围、缺少可靠版本标记或返回压缩分段时，取消并等待旧请求结束，最多一次完整下载回退。总期限不重置。文件版本变化/内容异常则拒绝解析。
- 普通网络/503/停滞失败终止全部请求，用户可取消或重试；不自动无限重试，也不缓存半成品。没有 WebCrypto 的环境使用原单请求路径。
- 测试导出中 `requestedTransport` 是请求策略，`transport` 为已实际观察到的 ranges/full/full-fallback；不把回退完成误标为分段成功。原单请求没有该实际字段时不推断。
