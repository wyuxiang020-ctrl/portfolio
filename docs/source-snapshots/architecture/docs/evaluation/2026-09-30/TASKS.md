# 真实读者与设备验收

版本 spatial-ux-2026-09-30-r1；状态：待执行，不是已取得的结果。

## 条件

招募 3—5 位未参与开发的读者，至少 2 位真实手机、1 位桌面，每人 10—15 分钟。用 P01 等匿名编号；录屏前征得同意，否则只记操作和原话。主持人不指按钮位置、不代操作。交替从 ITB / 祖母的火塘开始，减少顺序影响。

逐次记录日期、版本、完整 URL、设备型号、系统和浏览器版本、匿名/无痕、VPN 是否确认关闭、Wi-Fi/移动网络、运营商、首次/重复访问和缓存状态。系统代理关闭不等于 VPN 关闭；未知就写未知。无痕也不保证冷网络缓存。

## 给读者的任务

1. 阅读图纸后打开模型，用自己的话描述建筑与周边或院落的一项空间关系，并指出依据。记录原话，不由主持人补充答案。
2. 选择一个视角验证这项关系。观察默认镜头、视角名称、寻找控制入口的过程及迷失方向情况。
3. 隐藏挡住视线的部分。记录选中的名称、实际结果和误隐藏。祖母的火塘只有“场地与道路 / 建筑与院落”两组，不能单独隐藏屋顶；能力不足不算用户操作错误。
4. 恢复完整模型与总览。观察能否独立找到恢复入口，勾选和视角是否恢复。
5. 关闭模型，继续阅读附近正文，再打开一次。记录跳动、返回位置、是否要重新寻找入口。

追问：哪个名字难理解？默认画面先让你注意到什么？哪一步不知道该做什么？不要用“是不是更容易”诱导。

## 设备与异常检查

- 关闭 VPN，手机移动网络无痕访问正式入口与两个项目深链接。记录条件、成功/失败和截图。
- 桌面滚轮缩放、右键平移；手机单指旋转、双指缩放/平移、页面滚动与横竖屏。当前画布可能与页面滚动争夺手势，必须真机观察，尚未判定通过。
- 持续操作 30 秒，关闭/重开 3 轮，About → 返回项目 2 轮。记录白屏、卡顿、重复画布、控件失效和返回位置，不只保留成功轮。
- 慢网络加载中取消并立即重开；页面仍能继续阅读。解析阶段无法保证计算瞬间停止，保留任何卡顿。
- 本地 503 故障服务验证错误提示、重试和继续阅读；不要破坏生产网络做故障注入。

## 时间口径与保存

URL 加 `?modelTest=1#interactive-model`，在离开当前项目之前点击“下载本次测试记录”。仅保存在当前页内存，不自动上传；最多 20 次加载、每次 200 个操作事件。换页前单独保存，超过上限不能当完整日志。

录屏/秒表以点击打开为 T0：记肉眼首次可辨识模型 T1、首次拖动有反馈 T2、持续操作卡顿次数/最长停顿、每轮关闭重开。JSON 的 `clickToFirstRenderSubmittedMs` 是到首次 WebGL 调用完成；`controlsReadyMs` 是控件绑定就绪；两者均不等于实际屏幕显示或首次操作成功。`maxRenderSubmissionMs` 是 CPU 提交耗时，不是 FPS/GPU 时间；事件起止只用于对照录像。

每设备/网络至少 3 轮，明确缓存条件。重试次数不等于用户数。汇报 n、原始值、中位数和范围；失败保留在分母，区分下载、解析/图形和任务理解失败。

预先约定验收：5 项任务可连续执行，视角/恢复/关闭无需主持人指路，返回不迷失正文，手机无持续阻断滚动或控件不可达，加载可取消或失败重试。速度目标依据本轮设备基线与访客容忍反馈再确定，不事后挑数字。

下载是瓶颈 → 考虑轻量预览/反馈；绘制是瓶颈 → 定位高成本构件后优化；理解是瓶颈 → 作者校对图层语义和预设镜头。先确认模型轴向，“正面”不自动等于入口。不能由 AI 猜测“保留结构/改造前后”。真实反馈回来后再写第二轮针对性修改及前后效果。
